# Blender MCP Windows 使用手册

本目录是可单独分发的 Windows 部署包。接收者不需要克隆 `blender-mcp` 源码仓库；请保留本目录中的 PowerShell 脚本、wheel 和本手册。

## 1. 部署包内容

- `blender_mcp-1.9.1-py3-none-any.whl`：Blender MCP Python 包，供安装器和 tunnel-client 启动 MCP Server 使用。
- `install-addon.ps1`：把 wheel 中的 Blender Add-on 安装到本机 Blender 用户插件目录。
- `init.ps1`：检查依赖、按需安装 Add-on，并初始化名为 `blender-mcp` 的 tunnel-client profile。
- `start.ps1`：启动 tunnel-client；运行期间保持此 PowerShell 窗口打开。
- `blender-mcp.local.example.psd1`：本机配置模板。首次运行会复制成 `blender-mcp.local.psd1`。

本包**不包含** `uv`、`tunnel-client.exe`、Blender、Tunnel ID 或 API Key。每位使用者都必须配置自己的访问凭据。

## 2. 使用前的准备

在 Windows 上准备：

1. 已安装 Blender，并且当前 Windows 用户有权限写入 Blender 的用户插件目录。
2. 已安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，PowerShell 能执行 `uvx`。
3. 已安装 `tunnel-client.exe`，并已将其所在目录加入 Windows `PATH`。
4. 有权使用 [OpenAI Tunnels](https://platform.openai.com/settings/organization/tunnels)，并能取得本次连接所需的完整 Tunnel ID 和 [Runtime API Key](https://platform.openai.com/settings/organization/api-keys)。
5. 首次使用时能访问网络，以便 `uvx` 安装 wheel 的 Python 依赖。

建议把本目录解压到一个固定、自己有读写权限的位置。不要只复制某一个 `.ps1` 文件；脚本需要和 wheel 及配置模板放在同一目录。

打开一个新的 **Windows PowerShell 5.1** 窗口，进入实际部署目录，例如：

```powershell
Set-Location "C:\Tools\blender-mcp\windows"  # 替换为实际解压目录

Get-Command uvx
Get-Command tunnel-client
```

两条 `Get-Command` 都应能找到对应命令。如果找不到，请先安装相应工具或修正 `PATH`，然后重新打开 PowerShell。

如果执行脚本时被执行策略阻止，可以只对当前 PowerShell 窗口临时放行，不必修改整台机器的执行策略：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## 3. 配置 Tunnel ID

在部署目录执行：

```powershell
.\init.ps1
```

第一次运行时，脚本会创建 `blender-mcp.local.psd1`，随后停止并提示需要填写 Tunnel ID。这是预期行为。

编辑刚创建的文件：

```powershell
notepad .\blender-mcp.local.psd1
```

将 `TunnelId` 的占位值替换成 [OpenAI Tunnels 设置](https://platform.openai.com/settings/organization/tunnels)中分配给你的**完整 Tunnel ID**，不要自行编造 ID。例如，配置文件的结构如下：

```powershell
@{
    TunnelId = "<替换为实际的完整 Tunnel ID>"
}
```

保存文件。请不要把 API Key 写进这个配置文件。

> `blender-mcp.local.psd1` 是本机配置，不应随部署包分发或提交到 Git。每位使用者都应使用自己的 Tunnel ID。

## 4. 初始化部署

填写 Tunnel ID 后，再运行：

```powershell
.\init.ps1
```

默认流程会：

1. 检查部署目录中的 wheel。
2. 检查 `uvx` 和 `tunnel-client` 是否能从 `PATH` 找到。
3. 调用 `install-addon.ps1` 安装或更新 Blender Add-on。
4. 使用 `sample_mcp_stdio_local` 初始化名为 `blender-mcp` 的 tunnel-client profile。
5. 将控制平面 API Key 的读取方式配置为环境变量引用 `env:OPENAI_API_KEY`，而不是把密钥写进 profile。

初始化使用 `--force`。如果你的 tunnel-client 已有同名 `blender-mcp` profile，它会被重新生成。**如果该 profile 已用于其他服务，请先备份原 profile，确认可以替换后再初始化。**

### 不想在初始化时安装或更新 Add-on

可以跳过自动安装：

```powershell
.\init.ps1 -SkipAddonInstall
```

该参数只跳过 Add-on 安装；它仍会初始化 `blender-mcp` profile。只有在你确认现有 Add-on 与本包中的 MCP Server 兼容，或准备自行管理 Add-on 安装时，才建议使用。

## 5. 安装或更新 Blender Add-on

通常不必单独执行这一步，因为 `init.ps1` 默认会调用安装脚本。需要单独安装或更新时，执行：

```powershell
.\install-addon.ps1
```

安装脚本默认使用本目录中的 `blender_mcp-1.9.1-py3-none-any.whl`。

### 如果已经安装过 Blender Add-on，会发生什么？

对于标准 Blender 用户插件目录中的 MCP for Blender `.py` 插件：

- 安装器会识别已有的 MCP for Blender 插件文件，并将识别到的文件更新为 wheel 中的版本。
- 覆盖前会尝试把内容不同的旧文件备份到同目录的 `.py.bak` 文件，例如 `addon.py.bak`。
- 如果旧文件与待安装文件内容完全相同，则不需要重新备份。
- 安装器只会选择一个检测到的现有安装目录，不保证同时更新所有 Blender 版本各自的插件副本。

**建议：如果你手工修改过 Add-on，或旧版本对工作很重要，请在运行安装器前自行复制备份。** `.py.bak` 是便于恢复的单份备份，不应代替独立备份；再次安装其他版本时，同名备份文件可能被更新。

Blender 4.2 及以上版本还支持通过 Extensions 系统安装插件。目录型扩展与传统的单文件 `.py` Add-on 结构不同，当前安装脚本不保证能原位替换所有此类扩展。若你是从 Extensions 页面安装的旧版插件，请先在 Blender 中确认安装来源并备份；需要保留原扩展时，先用 `-SkipAddonInstall` 初始化，不要假设自动安装一定会覆盖原扩展。避免同时启用两份同名或功能重复的插件。

安装或更新后，建议关闭并重新打开 Blender；也可以在 Blender Preferences 中禁用再启用 `Interface: MCP for Blender`。随后在 Add-on 面板中点击 **Start MCP Server**。

## 6. 设置 API Key 并启动 tunnel

每次启动服务的 PowerShell 进程都必须能读取 `OPENAI_API_KEY`。请使用自己有权限使用的 [Runtime API Key](https://platform.openai.com/settings/organization/api-keys)，不要把密钥写进脚本、配置文件或发送给其他人。

以下方式会在当前 PowerShell 窗口中安全地提示输入密钥，不会把明文密钥直接写进命令历史：

```powershell
$secureKey = Read-Host "OpenAI Runtime API Key" -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secureKey)
try {
    $env:OPENAI_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
}
finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
}
```

然后运行健康检查：

```powershell
.\start.ps1 -Doctor
```

检查通过后，启动服务：

```powershell
.\start.ps1
```

服务会在当前窗口以前台方式运行。正常使用期间请保持该窗口打开；按 `Ctrl+C` 可停止它。关闭窗口或停止进程后，依赖此 tunnel 的 MCP 连接将无法继续调用。

## 7. 在 Blender 和 ChatGPT 中完成连接

1. 打开 Blender，进入 Preferences 中的 Add-ons/Extensions 管理页面，确认 `Interface: MCP for Blender` 已启用。
2. 点击 **Start MCP Server**。如果刚安装或更新过 Add-on，请先重启 Blender，或禁用后再启用该 Add-on。
3. 在运行 `.\start.ps1` 的同时，打开 [ChatGPT Connector 设置](https://chatgpt.com/#settings/Connectors)，创建或检查对应的 MCP Connector。
4. 保持 tunnel-client 进程运行，再从 ChatGPT 调用该 MCP。

`tunnel-client run --profile blender-mcp` 需要持续运行，才能进行 Connector 发现和后续 MCP 调用。

## 8. 常见问题

### `uvx` 或 `tunnel-client` 找不到

检查安装是否完成，以及可执行文件所在目录是否已加入 Windows `PATH`。修改 `PATH` 后请重新打开 PowerShell，再执行 `Get-Command uvx` 或 `Get-Command tunnel-client`。

### 提示 `OPENAI_API_KEY is not set`

在准备启动服务的同一个 PowerShell 窗口中重新设置 `OPENAI_API_KEY`，然后运行 `.\start.ps1 -Doctor`。该变量只在当前进程环境中设置时，不会自动出现在另一个新窗口中。

### 修改了 Tunnel ID，但连接仍然不正常

确认 `blender-mcp.local.psd1` 中填写的是完整、有效的 Tunnel ID；然后重新运行 `.\init.ps1` 生成 profile，再检查 API Key 和网络访问权限。

### MCP Server 已启动，但 Blender 操作不可用

确认 Blender 仍在运行，`Interface: MCP for Blender` 已启用，并且已点击 **Start MCP Server**。如果刚更新 Add-on，请重启 Blender 后再试。

### 更新后好像仍在运行旧版 Add-on

在 Blender 中禁用再启用 `Interface: MCP for Blender`，或完全重启 Blender。若电脑安装了多个 Blender 版本，请确认正在使用的版本与安装器更新的插件目录一致。

### 需要保留旧 Add-on

先把旧插件文件复制到其他目录保存。初始化时使用 `.\init.ps1 -SkipAddonInstall`，再单独安排旧插件迁移和版本兼容性验证。

## 9. 分发前检查

分发者应确认：

- 部署目录包含本手册、三个 `.ps1` 脚本、配置模板和 wheel。
- 不要把 `blender-mcp.local.psd1`、API Key 或其他个人凭据打包给接收者。
- 每位接收者都需要自己的 Tunnel ID 和 Runtime API Key。
- `tunnel-client.exe` 与 `uvx` 由接收者自行安装并配置到 `PATH`。
- 如果升级 wheel，请同步确认脚本、版本号和本手册中的版本说明。
